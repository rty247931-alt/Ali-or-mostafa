# متجر خُطوة — النسخة الكاملة

متجر أحذية إلكتروني: **Next.js 14 + TypeScript + PostgreSQL (Prisma)**. واجهة العملاء ولوحة الإدارة على قاعدة بيانات واحدة، وكل الأسعار والخصومات والشحن والمخزون تُحسب على الخادم.

> ## ⚠️ اقرأ هذا قبل التسليم للعميل
> الكود كُتب كاملًا لكنه **لم يُشغَّل على جهاز به Node وPostgreSQL** (بيئة الكتابة بلا إنترنت).
> ما اختُبر فعليًا: قواعد الحساب (الأسعار/الخصم/الشحن/حالات الطلب)، تشفير كلمات المرور، CSV، توقيع Paymob، حساب التواريخ بتوقيت القاهرة.
> **لذلك لا تسلّمه للعميل قبل أن تنفّذ «قائمة القبول» في آخر هذا الملف** (٣٠ دقيقة تقريبًا). أول تشغيل قد يُظهر أخطاء بسيطة؛ ابعت لي نصّ الخطأ وأصلحه.

## التشغيل بأمر واحد

المطلوب مرة واحدة: Node 20+ وقاعدة PostgreSQL فارغة (مجانية من neon.tech أو supabase.com).

```bash
npm install
npm run setup      # يسألك عن رابط القاعدة، ينشئ الجداول والبيانات الأساسية وحساب المالك
npm run dev        # أو للإنتاج: npm run build && npm start
```

`npm run setup` يعمل كل هذا تلقائيًا: ينشئ `.env` ويولّد `SESSION_SECRET` • ينشئ الجداول • يضيف قيود قاعدة البيانات (المخزون لا ينزل عن صفر…) • يملأ الأدوار والأقسام ومناطق الشحن (٢٧ محافظة) والصفحات • ينشئ حساب المالك بكلمة مرور تكتبها أنت (لا توجد كلمة افتراضية ولا حساب مخفي).

الواجهة: `/` • الإدارة: `/admin/login`.

## النشر (Vercel Pro + Neon)
> ⚠️ خطة Vercel المجانية ممنوعة تجاريًا؛ متجر العميل يحتاج Pro. التفاصيل الكاملة لكل خدمة في **GUIDE_AR.md**.
١. أنشئ قاعدة على Neon وانسخ الرابط. ٢. ارفع المجلد إلى GitHub واستورده في Vercel. ٣. أضف متغيرات البيئة: `DATABASE_URL` و`SESSION_SECRET` و`SITE_URL` (+ متغيرات الصور أدناه، إجباري على Vercel). ٤. من جهازك بنفس `DATABASE_URL`: `npm run setup`. ٥. Deploy.

## متغيرات البيئة (`.env.example`)
| المتغير | لماذا |
|---|---|
| `DATABASE_URL` `SESSION_SECRET` `SITE_URL` | أساسي |
| `STORAGE_DRIVER=s3` + `S3_ENDPOINT` `S3_BUCKET` `S3_ACCESS_KEY_ID` `S3_SECRET_ACCESS_KEY` `S3_PUBLIC_URL` `S3_REGION` | رفع صور المنتجات (Cloudflare R2 / AWS S3 / Supabase Storage). محليًا بدونها تُحفظ الصور في `public/uploads` |
| `RESEND_API_KEY` + `MAIL_FROM` | بريد: استعادة كلمة المرور، تأكيد البريد، إشعارات الطلبات. بدونها هذه الميزات تُعلن أنها غير مفعلة (لا تدّعي الإرسال) |
| `PAYMOB_API_KEY` `PAYMOB_INTEGRATION_ID` `PAYMOB_IFRAME_ID` `PAYMOB_HMAC_SECRET` | الدفع الإلكتروني (Paymob). عند Paymob اجعل رابط الـ callback: `SITE_URL/api/payments/paymob/webhook` |

## تفعيل الدفع الإلكتروني (لا يعمل بمجرد وضع المفاتيح)
أضف المتغيرات ← الإدارة ← الإعدادات ← «اختبار الاتصال» ← عند النجاح فقط يُسمح بتفعيل الدفع الإلكتروني. الطلب لا يُعتبر مدفوعًا إلا بإشعار Paymob الموقّع (HMAC) على الخادم؛ الرجوع لصفحة النجاح لا يثبت الدفع. **تكامل Paymob لم يُجرَّب على حساب حقيقي**: اختبره بوضع التجربة (Test) قبل الإطلاق.

## ما يشمله النظام (حسب ملف المتطلبات)
**العملاء:** شريط إعلانات • هوية وألوان من الإعدادات • واجهة رئيسية (واجهة قابلة للتعديل، أقسام، وصل حديثًا، عروض، الأكثر مبيعًا/مشاهدة من بيانات فعلية، بانرات، ماركات، آراء عملاء حقيقية، أسئلة شائعة، نشرة بريدية بموافقة) • متجر بكل الفلاتر والترتيب والترقيم والبحث • بطاقات المنتج (صورة بديلة، شارات، خصم محسوب، مقاسات سريعة، مفضلة) • صفحة المنتج (معرض وتكبير، ألوان ومقاسات بمخزون حقيقي، تقييمات موثقة، أسئلة، مشابهة، شوهد مؤخرًا، بيانات منظمة صادقة) • سلة وكوبون وشحن بالمحافظة وضريبة اختيارية • دفع كزائر أو بحساب (عند الاستلام / إلكتروني) • حساب (تسجيل، دخول، استعادة كلمة المرور، تأكيد البريد، عناوين، تفضيلات إشعارات، مفضلة، طلباتي، إعادة الطلب) • تتبع الطلب بحالة منفصلة للطلب والدفع والشحن وسجل زمني • صفحات المحتوى • SEO (robots، sitemap، canonical، OG، noindex للخاص) • وضع الصيانة.
**الإدارة:** لوحة إحصائيات حقيقية بفترة لكل رقم • منتجات (إضافة، تعديل كامل، صور متعددة بألوان، ألوان/مقاسات جديدة، إخفاء/إيقاف/أرشفة، حذف آمن، عمليات جماعية، استيراد وتصدير CSV) • مخزون بحركات وأسباب ومن/متى • طلبات (بحث، فلاتر، تغيير حالة بقواعد، ملاحظات، شحنة، استرداد مسجّل، فاتورة، قائمة تجهيز) • عملاء (بحث، ملاحظات داخلية، تصدير) • أقسام • ماركات • كوبونات • شحن (مناطق وأسعار وحد مجاني) • بانرات • صفحات المحتوى • تقييمات (اعتماد/إخفاء/رد) • أسئلة المنتجات • رسائل التواصل • إشعارات • مستخدمون وأدوار • تقارير (مبيعات يومية، مقارنة فترات، أفضل/أقل المنتجات، قسم، ماركة، مقاس ولون، طرق الدفع، عملاء جدد/عائدون، تصدير) • إعدادات المتجر.
**الأمان:** صلاحيات تُفحص على الخادم في كل عملية • scrypt • قفل الحساب بعد ٥ محاولات • `HttpOnly/SameSite/Secure` • فحص Origin • تحقق Zod على الخادم • Prisma (لا SQL Injection) • React (لا XSS) • حد للطلبات • رفع ملفات بفحص المحتوى الحقيقي والحجم وتصغير تلقائي إلى WebP • سجل عمليات بدون أسرار • لا أسرار في الواجهة.

## ما **لا** يشمله بعد (صراحةً)
تكامل شركة شحن آلي (تُسجَّل بيانات الشحن يدويًا مع رابط تتبع من قالب تضبطه، ولا يظهر تتبع لحظي) • اللغات والعملات المتعددة (المتجر عربي بالجنيه) • إرسال حملات النشرة (يُصدَّر المشتركون مع رابط إلغاء الاشتراك الموقّع لاستخدامهم في أداة بريد) • إلغاء جلسة مستخدم فورًا (الجلسات JWT تنتهي بعد ٧ أيام؛ إيقاف الحساب يمنع الدخول الجديد وعمليات الإدارة فورًا) • الحد من الطلبات مخزَّن في ذاكرة الخادم (سرعة مخففة لا حاجز نهائي) • بريد حملات النشرة • رسائل SMS/واتساب للعملاء.

## الاختبارات
- `npm test` ← اختبارات قواعد الأعمال و CSV وتوقيع Paymob.
- `SMOKE_OK=1 npm run smoke` ← **على قاعدة تطوير فقط**: يختبر فعليًا ٥ مشترين لـ٣ قطع، تكرار الطلب، كوبون منتهٍ وصالح، إلغاء يعيد المخزون مرة واحدة، قواعد الحالات، دفع COD عند التسليم. ينظّف بياناته بعد التنفيذ.

## قائمة القبول (نفّذها قبل التسليم)
| # | السيناريو | كيف | الحالة |
|---|---|---|---|
| ١ | منتج جديد من الإدارة يظهر في المتجر | الإدارة ← المنتجات ← إضافة (الحالة: نشط) | ☐ |
| ٢ | تغيير السعر ينعكس | عدّل السعر ← حدّث صفحة المنتج | ☐ |
| ٣ | لون ومقاس جديدان | المنتج ← إضافة لون/مقاس | ☐ |
| ٤ | منع مقاس غير متوفر | اجعل كمية مقاس ٠ ← زرّه معطّل في المتجر | ☐ |
| ٥ | حساب عميل ودخول | `/account` | ☐ |
| ٦ | سلة وطلب تجريبي | أضف ← السلة ← الدفع | ☐ |
| ٧ | منع التلاعب بالسعر | الخادم يتجاهل أي سعر من المتصفح (موثّق في الكود: `pricing.ts`) + `smoke` | ☐ |
| ٨ | منع كمية أكبر من المخزون | `npm run smoke` | ☐ |
| ٩ | منع خصم المخزون مرتين | `npm run smoke` (تكرار الطلب + الإلغاء) | ☐ |
| ١٠ | تحديث الحالة يظهر للعميل | غيّر الحالة ← «طلباتي» | ☐ |
| ١١ | عميل لا يرى طلب غيره | افتح `/order/<رقم طلب غيرك>` بحسابك: يجب أن يرفض | ☐ |
| ١٢ | موظف بلا صلاحية لا يعدّل الأسعار | أضف موظفًا بدور «مسؤول الطلبات» وجرّب | ☐ |
| ١٣ | كوبون صالح ومنتهٍ | `npm run smoke` + يدويًا | ☐ |
| ١٤ | الدفع في وضع الاختبار | بعد ضبط Paymob Test | ☐ |
| ١٥ | الموقع على الهاتف والكمبيوتر | افتحه على الاثنين | ☐ |
| ١٦ | نسخ احتياطي واستعادة | `npm run backup` ثم `npm run restore -- <الملف>` على قاعدة تجريبية | ☐ |

## النسخ الاحتياطي
`npm run backup` (يتطلب `pg_dump`) • الاستعادة: `npm run restore -- backups/<ملف>`. الأفضل أيضًا تفعيل النسخ التلقائي/الاستعادة لنقطة زمنية في Neon أو Supabase.
